Use the `dpm-build-product` skill for everything below. Follow it exactly.

The person running this has an offer written from `/dpm:shape-offer`. They are new to this and new to Claude Code. They are about to watch you write and run a script, which is the point in this course where people get nervous, so narrate what you are doing in plain words as you go.

**Before you say anything, find and read their offer.** Look for `offer.md` and `evidence-bank.md` in the project folder. Read the mechanism, the three S and the ladder table. If they passed a path in the arguments below, use that instead.

**If `offer.md` is missing**, stop and send them to `/dpm:shape-offer`. Do not offer to build from a description they type in the chat.

**If the ladder table has rows with no deliverable file path**, name those rows and stop. That table is the build list, and a row with no file is not a product yet.

**Otherwise**, open by saying the offer back to them in one line, then the ladder as a short list of what you are about to manufacture and roughly how long each piece takes. Then start Stage 1.

Hold it as a conversation, one question at a time. Argue with them about the countable unit and the number, because that decision runs the whole build.

Two things you must not do, whatever they say:

- **Do not draft more than five units before they have read and approved those five.** Then ten at a time, stopping after each batch. If they tell you to just write all of them, say plainly what happens when you do: the units come out individually fine and collectively identical, and that is what a refund request reads like.
- **Do not stop after the core product.** The lead magnet, the bump and the preview images come out of the same content file and cost almost nothing once the build script exists. Produce them without being asked, and run the refund audit twice.
